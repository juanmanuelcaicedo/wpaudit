CríticaWPA-001

Copia de wp-config.php accesible públicamente
Exposición de archivos · Esfuerzo bajo · Fuente: wpaudit

Descripción

Se puede descargar un respaldo del archivo de configuración con credenciales de base de datos y claves de seguridad.

Impacto

Compromiso total: acceso a la base de datos, posible toma de control del sitio y de los datos de usuarios.

Evidencia

GET /wp-config.php.bak → HTTP 200 (61 bytes; contenido omitido por seguridad)

Recomendación

Retire el archivo del directorio web, rote TODAS las credenciales afectadas y revise los registros de acceso por descargas previas. Cambie las salts/keys de wp-config.php y la contraseña de la base de datos.

Referencias

  • https://developer.wordpress.org/advanced-administration/security/hardening/
  • https://owasp.org/www-project-web-security-testing-guide/

AltaWPA-004

El sitio se sirve sin HTTPS
Transporte · Esfuerzo bajo · Fuente: wpaudit

Descripción

La URL auditada utiliza HTTP en claro. Credenciales, cookies de sesión y contenido viajan sin cifrar y pueden ser interceptados o alterados.

Impacto

Un atacante en la misma red (Wi-Fi público, proveedor) podría robar sesiones de administrador o inyectar contenido malicioso a sus visitantes.

Evidencia

URL auditada: http://127.0.0.1:8099

Recomendación

Instale un certificado TLS (p. ej. Let's Encrypt), redirija todo el tráfico HTTP a HTTPS y actualice las URLs de WordPress (Ajustes → Generales) a https://.

Referencias

  • https://owasp.org/www-project-web-security-testing-guide/
  • https://letsencrypt.org/getting-started/

MediaWPA-006

Enumeración de nombres de usuario posible
Autenticación · Esfuerzo bajo · Fuente: wpaudit

Descripción

Es posible obtener nombres de usuario válidos sin autenticarse (REST API y/o archivos de autor). Esto facilita los ataques de fuerza bruta y de credential stuffing.

Impacto

Los atacantes pueden dirigir ataques de contraseñas contra cuentas reales, incluidas las de administración.

Evidencia

GET /wp-json/wp/v2/users → 2 usuario(s) listados sin autenticación
/?author=1 redirige a /author/admin/
Usuarios expuestos: admin, ana

Recomendación

Restrinja el endpoint /wp/v2/users a usuarios autenticados, bloquee ?author=N y use 2FA en cuentas con privilegios.

Corrección sugerida: adáptala y pruébala antes de producción

// functions.php
add_filter('rest_endpoints', function ($e) {
  if (!is_user_logged_in()) {
    unset($e['/wp/v2/users'], $e['/wp/v2/users/(?P<id>[\d]+)']);
  }
  return $e;
});

# Apache: bloquear enumeración por ?author=
RewriteCond %{QUERY_STRING} (^|&)author=\d+ [NC]
RewriteRule ^ - [F]

Referencias

  • https://owasp.org/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/03-Identity_Management_Testing/04-Testing_for_Account_Enumeration_and_Guessable_User_Account

XML-RPC habilitado con métodos de riesgo
Superficie de ataque · Esfuerzo bajo · Fuente: wpaudit

Descripción

xmlrpc.php permite probar cientos de contraseñas en una sola petición (system.multicall) y usar el sitio como pivote en ataques de denegación de servicio (pingback.ping).

Impacto

BajaWPA-009

Panel de acceso (wp-login.php) expuesto a Internet
Autenticación · Esfuerzo bajo · Fuente: wpaudit

Descripción

El formulario de login es accesible desde cualquier IP. Es el punto de entrada de la mayoría de ataques de fuerza bruta contra WordPress. No se detectó CAPTCHA.

Impacto

Intentos masivos de adivinar contraseñas; si prospera uno, el atacante controla el sitio.

Recomendación

Active 2FA para administradores/editores, limite intentos fallidos, use contraseñas únicas largas y, si es posible, restrinja /wp-admin por IP o detrás de VPN/WAF. (No se probaron contraseñas durante esta auditoría.)

Corrección sugerida: adáptala y pruébala antes de producción

# Apache — restringir wp-login por IP
<Files wp-login.php>
  Require ip 203.0.113.10
</Files>

# Nginx
location = /wp-login.php { allow 203.0.113.10; deny all; fastcgi_pass ...; }

Referencias

BajaWPA-011

Cabeceras de seguridad HTTP recomendadas ausentes
Cabeceras HTTP · Esfuerzo bajo · Fuente: wpaudit

Descripción

Las cabeceras de seguridad reducen el impacto de ataques como clickjacking, MIME sniffing, fuga de referrer y XSS. Faltan: Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy.

Impacto

Menor defensa en profundidad frente a ataques en el navegador del visitante.

Evidencia

Ausente: Content-Security-Policy
Ausente: X-Frame-Options
Ausente: X-Content-Type-Options
Ausente: Referrer-Policy
Ausente: Permissions-Policy

Recomendación

Añada las cabeceras ausentes en el servidor web. Para CSP, empiece en modo Content-Security-Policy-Report-Only y ajuste según los recursos de su tema/plugins.

Corrección sugerida: adáptala y pruébala antes de producción

# Apache (.htaccess o vhost)
<IfModule mod_headers.c>
  Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
  Header always set X-Content-Type-Options "nosniff"
  Header always set X-Frame-Options "SAMEORIGIN"
  Header always set Referrer-Policy "strict-origin-when-cross-origin"
  Header always set Permissions-Policy "geolocation=(), microphone=(), camera=()"
</IfModule>

# Nginx (bloque server)
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;

Referencias

  • https://owasp.org/www-project-secure-headers/
  • https://developer.mozilla.org/docs/Web/HTTP/CSP

BajaWPA-013

La REST API refleja el Origin y permite credenciales (comportamiento estándar de WordPress)
Configuración del servidor · Esfuerzo bajo · Fuente: wpaudit

Descripción

El endpoint /wp-json/ devuelve Access-Control-Allow-Origin igual al Origin recibido y Allow-Credentials: true. Es el comportamiento por defecto del núcleo de WordPress; las acciones autenticadas por cookie exigen además un nonce, por lo que no permite leer datos de un usuario desde otro sitio. Se informa como endurecimiento opcional.

Evidencia

GET /wp-json/ con Origin: https://evil.example → ACAO: https://evil.example, ACAC: true

Recomendación

Si no usa la REST API desde otros dominios, restrinja los orígenes permitidos con el filtro rest_pre_serve_request o desde el servidor/CDN.

Referencias

  • https://developer.wordpress.org/rest-api/
